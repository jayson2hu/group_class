管理后台与课程列表拆分优化计划

本计划用于审阅管理后台和课程前台的拆分方案。核心方向是：普通用户只看到课程、拼课进度、报名与个人报名记录；后台使用独立文件和独立路由，面向管理员、运营、老师；登录注册支持公众号扫码、邮箱、用户名等方式，并由后台配置对应能力；管理员后台新增 SEO 管理能力，用于优化网站展示。

目标 已确认需求 前后台拆分 注册登录 开课配置 后台权限 SEO 里程碑 验收 待确认

1. 优化目标

课程前台独立 游客和普通用户只进入课程列表、课程详情、拼课进度、报名/候补/试听和个人报名记录。
管理后台独立 后台使用独立文件、独立路由、独立导航，避免和课程列表耦合，不向普通用户暴露后台入口。
登录注册多途径 支持公众号扫码、邮箱、用户名登录；注册支持公众号扫码关注和邮箱方式，不再依赖短信服务。

3. 前后台拆分方案

3.1 前台：课程报名与拼课中心

  • 必须 前台默认首页展示课程列表、课程详情、拼课进度、剩余名额、开课状态、报名入口。
  • 必须 游客可查看公开课程和拼课情况，但不能看到管理后台入口。
  • 必须 登录用户可进入“我的报名”，查看历史拼课、待拼课、待开课、已取消、已完成等记录。
  • 必须 “我的报名”支持取消报名、修改资料、查看缴费状态。
  • 必须 前台导航只包含课程、我的报名、登录/注册或用户信息。

3.2 后台：独立管理工作台

  • 必须 新增独立后台入口文件，例如 admin.html。
  • 必须 后台使用独立路由空间，例如 /admin.html#/classes、/admin.html#/registrations、/admin.html#/seo。
  • 必须 后台 JS、CSS、路由守卫尽量独立，不复用前台主导航和页面壳。
  • 必须 普通用户 token 访问后台时显示无权限或跳转后台登录，不展示后台数据。

3.3 推荐文件与路由结构

入口 路由 页面 访问对象
index.html #/public/classes 课程列表、拼课进度 游客、普通用户
index.html #/login、#/register 普通用户登录/注册 游客、普通用户
index.html #/account/registrations 我的报名、历史拼课、待开课 普通登录用户
admin.html #/login 后台登录 管理员、运营、老师
admin.html #/classes、#/registrations、#/accounts、#/seo 课程管理、报名管理、账号管理、SEO 管理 后台角色

4. 注册登录优化计划

4.1 普通用户注册

  • 必须 注册途径 1：通过扫码关注公众号进行登录/注册绑定。
  • 必须 注册途径 2：通过邮箱注册。
  • 必须 后台提供单个公众号登录配置：公众号二维码、AppID、AppSecret、回调地址、启用状态，并允许管理员决定是否启用为登录或注册方式。
  • 必须 后台提供邮箱登录配置：SMTP 服务、发件邮箱、授权码或密钥、验证码有效期、启用状态。
  • 必须 邮箱注册流程采用“邮箱 + 验证码 + 基础资料”的方式，验证码有效期 5 分钟。
  • 建议 注册后补充家长姓名、学生姓名、学生年级，用于报名资料自动带出。

4.2 普通用户登录

  • 必须 登录方式 1：扫描二维码登录，二维码可引导关注公众号并完成登录绑定；是否启用由管理员后台配置决定。
  • 必须 登录方式 2：邮箱验证码登录，验证码有效期 5 分钟。
  • 必须 登录方式 3：用户名登录，普通用户和后台用户均可使用；普通用户需先通过公众号或邮箱等方式完成注册。
  • 必须 登录页不再出现后台演示账号说明。
  • 必须 从报名页触发登录后，登录成功需要回到原课程报名流程。

4.3 后台登录

  • 必须 后台登录放在 admin.html#/login，不和普通用户登录页混用。
  • 必须 后台登录支持用户名登录；是否支持邮箱/扫码由后台配置决定。
  • 必须 登录成功后校验角色，只有管理员、运营、老师可以进入后台。
  • 必须 角色不匹配时显示“当前账号无后台权限”，并禁止进入后台路由。

5. 开课与课程配置字段

  • 必须 课程必须有课程名称。
  • 必须 开课等级由创建人决定，用于区分课程层级或开课层级。
  • 必须 开课等级支持对应标识，例如等级标签、图标或短代码。
  • 必须 课程展示颜色由创建人自己设置，用于在列表和详情页中区分课程。
  • 必须 开课配置新增微信号字段，用于展示或后台联系。
  • 必须 开课配置新增手机联系方式字段，用于展示或后台联系。
  • 必须 游客不展示课程详细隐私信息。
  • 必须 登录用户可以看到用户微信，不可以看到隐私手机号码。
  • 必须 管理员、运营、老师可以查看微信号和手机联系方式。

6. 后台角色与账号管理

角色 权限范围 账号管理能力
管理员 最高权限，可访问全部后台功能，包含课程、报名、账号、配置、SEO。 可添加、删除、禁用、修改全部账号，包含普通用户、运营、老师。
运营 管理课程、报名、拼课进度、缴费状态、联系信息和部分配置。 可管理老师账号和普通用户账号；不允许管理管理员账号。
老师 查看和维护自己相关课程、报名跟进、学生信息、开课状态。 默认不允许新增或删除账号。

7. 管理员后台 SEO 优化能力

  • 必须 后台新增完整 SEO 管理页面，仅管理员可完整管理。
  • 必须 支持配置网站标题、描述、关键词、首页 SEO、课程列表 SEO、课程详情 SEO 模板。
  • 必须 支持配置 Open Graph / 分享标题、分享描述、分享图片。
  • 必须 支持生成或维护 sitemap.xml 和 robots.txt。
  • 必须 支持课程详情页按课程名称、年级、课程等级、开课状态生成动态 meta 信息。
  • 必须 SEO 配置保存后提供预览，避免错误标题或描述影响公开页面。

9. 验收标准

  • 通过 游客打开前台，只看到课程、拼课进度、登录/注册，不看到管理后台入口。
  • 通过 游客可查看公开课程拼课进度和开课情况。
  • 通过 普通用户登录后，可查看历史参加拼课、待拼课、待开课记录。
  • 通过 普通用户可取消报名、修改资料、查看缴费状态，但不能个人线上付款。
  • 通过 管理员、运营或老师可在后台维护缴费状态。
  • 通过 admin.html 独立运行，后台导航、样式、路由不依赖前台页面壳。
  • 通过 管理员可新增、删除、禁用、修改全部账号；运营可管理老师和普通用户账号。
  • 通过 后台可配置单个公众号扫码登录和邮箱验证码登录所需参数，管理员可决定启用哪些登录/注册方式。
  • 通过 邮箱验证码有效期为 5 分钟。
  • 通过 后台可维护完整 SEO 配置，并能影响前台页面 meta 信息、sitemap、robots 和分享信息。
  • 通过 开课等级、等级标识、课程颜色和课程名称在创建课程时可配置，课程颜色由创建人自己设置。
  • 通过 游客不展示详细隐私信息；登录用户可见微信但不可见隐私手机号；后台角色可见手机号。

## 1. 项目概述

### 1.1 项目名称
拼课课程看板与创建管理系统

### 1.2 项目目标
建立一个支持“管理员 / 指定发起人创建拼课课程、用户通过看板查看并报名、运营统一管理课程状态与报名数据”的产品系统，替代微信群内重复发接龙的招生方式。

### 1.3 一句话定义
把“群里反复发接龙”的非结构化招生流程，升级为“可创建、可审核、可展示、可报名、可管理”的拼课组班系统。

---

## 2. 背景与问题

当前英语课程招生主要依赖微信群聊天和接龙，存在以下问题：

1. 群内重复刷屏
   - 不同年级、不同班型、不同时间段的接龙反复发送。
   - 家长容易疲劳，群体验差。

2. 信息分散
   - 课程时间、价格、适合对象、差几人成班等信息分散在聊天记录中。
   - 用户很难快速做决策。

3. 接龙不等于有效报名
   - 群里回复“1. 张三”只能代表意向，无法沉淀结构化报名数据。
   - 人数统计不准确，影响成班判断。

4. 运营成本高
   - 老师/运营需反复答疑、统计人数、催报名、更新成班情况。

5. 缺少课程供给管理能力
   - 当前无法规范“谁可以发起新拼课课程”。
   - 缺少审核、模板、状态流转、负责人机制，容易导致课程混乱。

因此，需要建设一个同时面向 C 端用户与 B 端运营的拼课管理系统。

---

## 3. 业务目标

### 3.1 业务目标
1. 替代群内接龙，统一报名入口。
2. 提升课程成班效率和报名转化率。
3. 降低群消息刷屏和人工运营成本。
4. 支持管理员 / 指定发起人灵活创建拼课课程。
5. 建立可控的课程审核与发布机制。
6. 为后续支付锁位、候补、自动通知等能力打基础。

### 3.2 用户目标
对家长/学员：
- 快速看到有哪些班。
- 看懂每个班的时间、价格、适合对象、成班进度。
- 直接报名、试听、候补。

对管理员/运营：
- 创建和维护拼课课程。
- 控制谁能创建课程。
- 跟踪报名人数、状态、负责人。
- 不再依赖群接龙统计。

## 4. 用户角色与权限

### 4.1 超级管理员
权限：
- 创建任意课程
- 编辑任意课程
- 发布 / 下架 / 删除课程
- 审核指定发起人提交的课程
- 配置课程模板
- 配置角色与权限
- 查看全部报名数据
- 指派课程负责人

### 4.2 课程管理员
权限：
- 创建课程
- 编辑自己负责的课程
- 查看和导出自己课程的报名数据
- 更新课程状态
- 管理候补与转班

限制：
- 不可修改平台级权限配置
- 不可删除其他管理员的课程

### 4.3 指定发起人
适用对象：老师、班主任、渠道负责人等。

权限：
- 创建拼课课程草稿
- 基于模板创建课程
- 提交课程审核
- 查看自己发起课程的状态和报名情况

限制：
- 默认不可直接发布课程（需审核）
- 不可修改他人课程

### 4.4 普通用户（家长/学员）
权限：
- 查看课程看板
- 查看课程详情
- 提交报名 / 候补 / 试听申请

## 6. 核心业务流程

### 6.1 创建与发布流程
1. 管理员/指定发起人进入后台创建课程。
2. 填写课程信息并保存为草稿。
3. 指定发起人提交审核。
4. 管理员审核通过后发布。
5. 发布后的课程出现在前台看板。
6. 用户报名后，课程人数与状态同步更新。

### 6.2 报名流程
1. 用户进入课程看板。
2. 查看课程卡片及状态。
3. 点击查看详情。
4. 点击立即报名。
5. 填写报名表。
6. 提交成功后进入“已报名”记录。

### 6.3 候补流程
1. 用户进入已满员/候补中的课程。
2. 点击加入候补。
3. 填写候补信息。
4. 后台记录候补名单。
5. 若有空位，运营通知转正。

### 6.4 拼课失败处理流程
当到报名截止时间仍未达到最低成班人数：
- 课程可配置为自动取消 / 延期 / 转候补 / 推荐相近课程。
- 运营可手动处理并通知相关报名人。

## 8. 状态设计

### 8.1 课程状态
1. 草稿
2. 待审核
3. 报名中
4. 即将成班
5. 已成班
6. 进行中
7. 已满员
8. 候补中
9. 已结束
10. 已取消

### 8.2 状态定义
- 报名中：已发布且离成班仍有较大距离
- 即将成班：已达到约 60% 以上成班门槛
- 已成班：达到最低成班人数
- 进行中：课程已开课
- 已满员：达到最大人数
- 候补中：不可直接报名，仅可登记候补

### 8.3 建议状态切换规则
- 当前报名人数 < 60% 最低成班人数：报名中
- 当前报名人数 >= 60% 且 < 最低成班人数：即将成班
- 当前报名人数 >= 最低成班人数：已成班
- 当前报名人数 >= 最大人数：已满员
- 开课日期已到：进行中

## 11. 非功能需求

1. 前台页面在手机端可用，优先适配微信群内打开场景。
2. 核心流程应在 1 分钟内完成：查看课程 -> 判断适合 -> 提交报名。
3. 后台权限需做基本隔离，避免普通用户看到管理入口。
4. 课程状态与人数数据应一致，避免前后台错乱。
5. 所有已发布课程应支持分享链接。

## 12. 验收标准

## 12.1 前台验收

### AC-01 课程列表展示
- 用户进入首页后，可看到所有已发布课程。
- 每个课程展示名称、时间、价格、人数、状态。

通过标准：
- 未发布课程不可见。
- 已发布课程信息完整展示。

### AC-02 差额展示正确
- 未成班课程需展示“还差 X 人成班”。
- 已成班课程展示“已成班”。
- 已满员课程展示“已满员”。

通过标准：
- 计算逻辑与配置一致。

### AC-03 详情页可查看
- 用户点击课程卡片后，可进入详情页查看完整信息。

通过标准：
- 详情页包含课程目标、适合对象、规则说明。

### AC-04 支持立即报名
- 用户可提交报名表单。

通过标准：
- 必填字段校验通过。
- 后台成功生成报名记录。

### AC-05 支持候补
- 满员/候补课程展示“加入候补”按钮。

通过标准：
- 提交后后台生成候补记录。

---

## 12.2 后台验收

### AC-06 管理员可创建课程
- 超级管理员和课程管理员可创建课程。

通过标准：
- 创建成功后可保存为草稿或直接发布（按权限）。

### AC-07 指定发起人可创建草稿
- 指定发起人可基于模板或空白表单创建课程草稿。

通过标准：
- 可保存成功。
- 不可越权直接发布（若配置需审核）。

### AC-08 审核流正确
- 指定发起人提交后状态变为待审核。
- 管理员审核通过后变为报名中。
- 驳回后返回草稿或驳回状态。

通过标准：
- 前后台状态一致。
- 前台仅显示已发布课程。

### AC-09 模板可复用
- 创建人可选择模板并自动带入默认字段。

通过标准：
- 模板字段正常填充。
- 可修改允许编辑的字段。

### AC-10 权限隔离
- 普通用户不可见后台入口。
- 指定发起人不可编辑其他人课程。
- 非管理员不可修改平台配置。

通过标准：
- 无越权行为。

### AC-11 报名管理可用
- 运营可查看、导出、备注报名记录。

通过标准：
- 报名数据与前台提交一致。

## 12.3 业务验收

- 不需要依赖群聊天补充关键决策信息。

## 14. 风险与注意事项

1. 课程状态更新不及时会降低用户信任。
2. 报名人数不等于支付人数，后续需设计支付状态。
3. 如果模板和审核机制缺失，课程供给会变乱。
4. 若候补、调班、不成班规则不清晰，容易引发投诉。
5. 前台信息必须足够透明，否则用户仍会回到群里反复提问。
